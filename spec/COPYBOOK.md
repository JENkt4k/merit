# COBOL copybook migration toolkit v1

`merit-copybook` is a deterministic edge tool for strangler migrations. It does **not** make COBOL storage representations part of Merit language semantics. It parses a constrained copybook, verifies byte-level legacy records, and generates a stable canonical Merit declaration that can sit behind an audited adapter.

## Supported v1 subset

| COBOL construct | v1 behavior |
| --- | --- |
| `01`-`49` records/groups | accepted |
| `PIC X`, `PIC X(n)` | CP037 EBCDIC DISPLAY |
| `PIC 9`, `PIC 9(n)` | unsigned zoned DISPLAY |
| `PIC S9...` | signed zoned DISPLAY |
| implied decimal `V` | exact Python `Decimal`; no binary floating point |
| `COMP-3`, `PACKED-DECIMAL` | packed BCD with C/F positive and D negative sign |
| `COMP`, `COMP-4`, `COMP-5`, `BINARY` | canonical big-endian signed/unsigned binary adapter representation |
| fixed `OCCURS n TIMES` | accepted and flattened deterministically |
| `REDEFINES` | rejected; requires an explicit migration policy |
| `OCCURS DEPENDING ON` | rejected; requires an explicit migration policy |
| levels `66`, `77`, `88` | rejected by the v1 parser |

`COMP-5` is normalized to the toolkit's canonical big-endian binary representation. A platform adapter for a concrete source compiler must establish the source byte order before handing bytes to this codec; the toolkit never guesses host-native representation.

## Commands

```bash
merit-copybook inspect examples/copybooks/transfer.cpy
merit-copybook generate examples/copybooks/transfer.cpy --module legacy_transfer
merit-copybook verify examples/copybooks/transfer.cpy examples/copybooks/transfer.golden.json
```

`inspect` emits a JSON manifest containing source lines, field offsets, element/storage lengths, picture semantics, usage and record length. This manifest is intended to be versioned beside a migration and reviewed like an ABI.

`generate` emits canonical Merit declarations. Text fields become fixed stable byte structs, scaled numeric fields become exact Merit decimal types, integer numeric fields become `i64`/`u64`, and fixed OCCURS elements become explicit stable fields. The generated type is intentionally a canonical record, not a claim that its C layout aliases the original COBOL bytes.

`verify` performs both directions for every golden vector:

```text
canonical values -> COBOL bytes == expected bytes
expected COBOL bytes -> canonical values == expected values
```

This is the first half of a differential migration harness. In production, golden vectors should be exported from the incumbent COBOL implementation or independently generated by the source platform so the two implementations do not share an oracle.

## Safety properties

- Record length must match exactly.
- Every input key must match the schema exactly.
- Decimal scale overflow is rejected instead of rounded implicitly.
- Numeric precision/storage overflow is rejected.
- Invalid zoned/packed digits and sign nibbles are rejected.
- Unsupported copybook constructs fail closed with source-line diagnostics.
- EBCDIC conversion is explicit and codec-selectable; v1 defaults to IBM CP037.
- Generated Merit uses exact decimal declarations and stable canonical layouts.

## Migration architecture

```text
copybook + source-platform golden bytes
              |
              v
       merit-copybook
      /      |       \
 manifest  codec     generated Merit canonical type
      \      |       /
       audited adapter
              |
              v
       Merit financial kernel
```

The next expansion should add explicit dialect/platform profiles (IBM Enterprise COBOL, Micro Focus, etc.), signed DISPLAY variants, `REDEFINES` as tagged/overlay schemas, variable OCCURS with explicit length authority, copybook inclusion/replacement, and a generator for C adapter shims. Those belong here at the migration boundary, not as implicit conversions in the Merit compiler.
